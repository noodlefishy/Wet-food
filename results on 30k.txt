Moving to INT8 is the single biggest performance upgrade you can give the RP2040. 

Because the Raspberry Pi Pico's RP2040 has **no hardware floating-point unit (FPU)**, every single float multiplication is emulated in software (taking 50–100 clock cycles per operation). Furthermore, streaming 1.25 MB of float weights over the SPI flash bus every few tokens creates a heavy I/O bottleneck.

Here is an architectural walkthrough of how INT8 quantization works, from the math to binary layout to the MicroPython inference loop.

---

### 1. The Core Idea: Symmetric Per-Row Quantization

Instead of storing each weight as a 32-bit float (4 bytes), you map the weights into an 8-bit signed integer (`int8`, ranging from `-127` to `+127`, taking only **1 byte**).

For each row $i$ in a linear layer matrix:
1. Find the maximum absolute float value in that row:
   $$\text{max\_val} = \max(|W_{i}|)$$
2. Compute a single 32-bit float scaling factor:
   $$\text{scale}_i = \frac{\text{max\_val}}{127.0}$$
3. Quantize the entire row into 8-bit integers:
   $$W_{\text{int8}, i, j} = \text{round}\left(\frac{W_{i, j}}{\text{scale}_i}\right)$$

When computing the dot product during inference, you reconstruct the float output by factoring the scale out:
$$\text{Output}_i = \text{scale}_i \times \sum_{j} \left( W_{\text{int8}, i, j} \times X_j \right) + \text{Bias}_i$$

---

### 2. How the Binary `.model` File Changes

Right now, your model weights are saved row-by-row as continuous 4-byte floats.

#### Current FP32 Layout (Rows of 80 features):
```text
[ Weight 0 (4B) ][ Weight 1 (4B) ] ... [ Weight 79 (4B) ]  --> 320 bytes per row
```

#### New INT8 (W8A32) Layout:
For each row, you write a 4-byte float `scale`, followed immediately by 80 `int8` bytes:
```text
[ Scale (4B float) ][ W0 (1B) ][ W1 (1B) ] ... [ W79 (1B) ] --> 84 bytes per row!
```

* **Size Reduction:** From 320 bytes down to 84 bytes per row (**~74% smaller**).
* **Total File Size:** `pico1 weights.model` drops from **~1.25 MB down to ~330 KB**.
* **Flash Headroom:** It easily fits in the Pico’s 2 MB flash with massive room to spare.

---

### 3. How the MicroPython Engine Runs It

In `meow.py` and `miaou.py`, your inner loop `stream_linear` changes from reading 4-byte floats (`f`) to reading 1-byte signed characters (`b`).

#### Current FP32 `stream_linear`:
```python
@micropython.native
def stream_linear(f, r, c, x):
    out, bv = [0.0]*r, memoryview(BUF)[:c*4]
    for i in range(r):
        f.readinto(bv)
        row = struct.unpack(f'{c}f', bv)   # Unpacks 4-byte floats
        out[i] = sum(row[j]*x[j] for j in range(c))
    # ... add bias ...
    return out
```

#### New INT8 `stream_linear`:
```python
@micropython.native
def stream_linear_int8(f, r, c, x):
    out, bv = [0.0]*r, memoryview(BUF)[:c]  # Buffer is 4x smaller (c bytes instead of c*4)
    for i in range(r):
        # 1. Read the 4-byte row scale
        scale = struct.unpack('f', f.read(4))[0]
        
        # 2. Read c bytes directly into buffer (75% less SPI flash traffic!)
        f.readinto(bv)
        
        # 3. Unpack as signed 8-bit integers ('b')
        row = struct.unpack(f'{c}b', bv)
        
        # 4. Multiply integer weights with activations, then scale once per row
        dot = sum(row[j] * x[j] for j in range(c))
        out[i] = dot * scale
        
    # Read and add FP32 biases at the end
    bi = 0
    while bi < r:
        s = min(64, r - bi)
        f.readinto(memoryview(BUF)[:s*4])
        b = struct.unpack(f'{s}f', memoryview(BUF)[:s*4])
        for i in range(s): out[bi+i] += b[i]
        bi += s
    return out
```

---

### 4. Why This Accelerates the RP2040

#### A. The SPI Flash Bottleneck (4x Speedup in I/O)
On the Pico, streaming binary weights from the external Winbond SPI flash chip takes real clock cycles. Because the model file shrinks from 1.25 MB to ~330 KB:
* `f.readinto()` reads **80 bytes** instead of **320 bytes** per row.
* SPI bus read time per token drops by **~75%**.

#### B. Integer Arithmetic via the Hardware Multiplier
The RP2040's ARM Cortex-M0+ silicon includes a hardware integer multiplier (`MULS`) that executes **32-bit integer multiplication in 1 clock cycle**.
* In pure FP32, multiplying two software floats calls the Pico bootrom runtime software emulation (`__aeabi_fmul`), which costs dozens of instructions.
* By quantizing weights to `int8`, you offload multiplication to the integer ALU, saving thousands of cycles per layer.

---

### 5. How to Quantize: Post-Training Quantization (PTQ)

You do **not** need to retrain your model from scratch to get INT8 weights. You train normally in PyTorch using FP32, and then run a quantization script on the exported model:

```python
def quantize_row_int8(weight_row_tensor):
    max_val = weight_row_tensor.abs().max().item()
    scale = max_val / 127.0 if max_val > 0 else 1.0
    int8_weights = torch.clamp(torch.round(weight_row_tensor / scale), -128, 127).to(torch.int8)
    return scale, int8_weights.numpy().tobytes()
```

You write the 4-byte float `scale`, followed by the raw `int8` byte string, straight into the `.model` file.

Because your task universe is closed (1,024 words, bounded state space), **INT8 post-training quantization has virtually zero impact on reasoning accuracy** (typically $<0.2\%$ degradation), while slashing latency and memory usage dramatically.
